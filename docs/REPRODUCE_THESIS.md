# One-command thesis reproduction from exported evidence

Target: the 25 listed tables and nine figures in `thesis_full_project-4.pdf`. This workflow reads the committed snapshots, predictions, recorded timing measurements and dependence-cell exports. It does **not** require a database, `Train.py`, nn-Dataset, nn-GPT, image datasets, GPU access, candidate training or Qwen refitting.

## Setup

Use Python 3.11 and a TeX installation with `pdflatex`, the standard article class and fontenc. Python dependencies are pinned to the tested CPU environment in `requirements-reproduce.txt`.

From the repository root:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-reproduce.txt
python -B run_all.py --check
python -B run_all.py --out recomputed/thesis
```

The final command performs the complete workflow. Use a fresh output directory: existing paths are refused, not reset or overwritten. `python -B run_all.py --list` prints the covered table/figure identifiers without running calculations. The runner performs no network requests or automatic dependency installations.

## Outputs

```text
recomputed/thesis/
  tables/                  table_4_1.csv/.md/.tex, ..., table_A_5.csv/.md/.tex
  figures/                 figure_4_1.pdf/.png, ..., figure_6_5.pdf/.png
  tables.json              all regenerated table values in one machine-readable file
  main_sources.json        exact condition/seed-to-archive-member mapping
  work/                    extracted input packet and fresh analysis reports/diagnostics
  complete.json            complete coverage, input/source hashes and environment
  README.md                interpretation and known differences
```

`complete.json` is written only after all 25 tables and nine figures have been produced and frozen input hashes rechecked. A failed run retains its partial output and `FAILED.txt` for diagnosis; it does not silently mark missing analyses complete. There is no implicit resume or cleanup. The `recomputed/` destination is Git-ignored.

Tables are exported as readable long/wide CSV, Markdown and basic LaTeX tabular fragments. They retain all five metrics where relevant and can contain additional provenance/diagnostic columns. They reproduce the numerical content, not the exact thesis page layout. Figure styling also need not be pixel-identical to the thesis PDF.

## What is recomputed

- **4.1:** count the actual frozen exported records, retaining classification versus other tasks.
- **4.2–4.4:** render documented target/statistic/input definitions. These are design tables, not empirical estimates.
- **6.1:** aggregate the archived MIC cells and significance decisions separately by analysis stream. The dCor heatmap BH values are independently checked from saved analytical p-values.
- **6.2–6.9 and A.1–A.3:** read exact archived condition/seed predictions; recompute means, seed intervals and paired-bootstrap results where the table calls for them. The direct comparison uses NumPy seed 0; historical combination/ZCP scripts preserve their Python `random.Random(0)` convention. Individual-layer comparison preserves its separate NumPy RNG.
- **6.10–6.11 and A.4:** execute existing LODO/LOFO readers, verify receipts/prompts/architecture identities, and recompute architecture-grouped bootstrap intervals. Original inputs and reference reports travel together in the extracted packet.
- **6.12:** recompute metrics from saved original-proxy and common-calibration predictions on their exact 86-record test cohort. The common-cohort calibrators are not refitted by this runner; their separate recovery/reproduction entry point remains available.
- **6.13:** average actual saved timing records from the 96 complete layer candidates and the separate 96 successful ZCP candidates; verify the 93-candidate intersection. No new timing benchmark is run.
- **6.14–6.16 and A.5:** recompute NB201 metrics, primary tests and supporting analyses from panels, including the crossed statistical mixed-model sensitivity fits. Classical adjusted intervals use saved predictions, not fresh classical predictor training. Statistical mixed-model fitting is not neural-network training.
- **All figures:** regenerate schematics from their existing source; generate the Taylor summary, dependence plots and six-seed cost/RMSE plot from the recomputed tables/exported cells.

## Important boundaries

1. The dependence estimator and its 200-permutation MIC tests are **not** rerun from raw network checkpoints. The reported tables/figures are regenerated by aggregating the frozen exported per-cell estimates. This is intentional and is recorded in output provenance.
2. LEMUR used test-informed feature selection. Regeneration does not convert those comparisons into confirmatory experiments.
3. The initial two-accuracy/no-layer RMSE recomputes to `11.471549990343567` (four-decimal `11.4715`), whereas the thesis retained `11.4716`. The runner reports this known last-digit difference and keeps the computed value.
4. NB201 target policies and primary populations differ by dataset. Supporting mixed-model optimizer behavior may vary by numerical environment; mismatches/unverified fits are reported rather than replaced with historical numbers.
5. The summary plot uses LEMUR's all-115 paired bootstrap and NB201's threshold-restricted record-paired t intervals. Those are not identical uncertainty constructions.
6. The cost plot uses six seeds and **ZCP ON**, not the selected ZCP-OFF configuration. Costs refer to a checkpoint, not an end-to-end search.
7. Archived reports/transcriptions are reference evidence only. The runner executes numerical readers and produces new reports; it does not relabel copied historical logs as new execution.

## Tests

```bash
python -B -m unittest discover -s tests -p "test_*.py" -v
```

These are focused tests of this reproduction workflow, not the historical framework/training suite. The full `run_all.py --out ...` execution is the end-to-end check. Source archives are preserved, traversal entries are refused, and existing output paths are never overwritten.
